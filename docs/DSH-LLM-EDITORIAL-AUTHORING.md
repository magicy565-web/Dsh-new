# 四技能驱动的编辑设计：0.4 执行记录

2026-10-26。用户否定旧 Allbirds 固定模板产物，要求技能包驱动 LLM 做设计。此前的程序检查和截图不能作为该产物的设计验收。本次修正的是插件创作路径，不是重新批准旧作品。

## 当前创作路径

四个技能的原始正文与资源继续保留。原生运行约定指导当前 DSH 模型完成资料研究、编辑选题、原创文案、文字编排、图文叙事、HTML/CSS/JS 实现和看图修订。模型使用原生 write/edit 写作品；没有额外模型客户端或 Agent 循环。

默认注册 `buyer_magazine_collect_site` 和 `buyer_magazine_review_artifact`。旧 issue JSON 编译器仅在 `legacyCompiler: true` 时注册，保留已有模块/Sourcing 的兼容调用。审阅工具读取作者原文件与本地素材，生成真实截图、PDF 和页图，不套版、不改写文件。返回的 `observed` 只表示机械检查结果。

## 已验证的工程事实

- `npm run check`：237 项通过；覆盖默认工具路由、旧输入兼容、Session 文件边界、Apify 协议与缺失凭据行为。
- 官方 SDK 测试：14 次原生工具分派通过。此测试没有模型执行，不能单独证明设计流程。
- 官方技能发现：四个技能和兼容入口可发现，原始资源保留。
- Chromium 合成检查：自由 DOM、本地 CSS/JS、实际改变文字的交互、手机截图与 PDF；额外验证弹窗不能绕过请求限制，以及打印元数据满足宿主的无损 JSON 要求。
- 原生 DeepSeek 模型首轮执行：实际加载四个技能和设计/字体资源，通过 write/edit 自行创作中文合成材料小刊；反复调用截图工具并修改作者文件，未调用旧固定模板生成器。

首轮原生运行发现打印返回值包含 `undefined` 字段，DSH 因无损 JSON 校验拒绝该结果。已修复为明确的空值并补充回归检查。复验对同一作者文件返回两页 PDF 和两张页图，完成 1440px 桌面、375px 手机及交互后截图；原生记录有 8 次审阅调用、一次 official present（HTML/PDF）和 completed 结束状态。模型同时记录了打印小字和大块留白的问题。这个验证使用明确标注的合成、文字主导材料，不是网站研究，也不是商业成品验收。

## Apify 环境状态

插件调用实际 `apify/website-content-crawler` Actor，保留 run/dataset ID 和原始 JSON 附件；未配置时返回 `APIFY_NOT_CONFIGURED`，不静默改用其他采集器。默认每次费用上限 USD 1、最多 30 页、180 秒。

本聊天的环境配置草稿已新增 `APIFY_TOKEN` 密钥要求，允许域名 `api.apify.com`。复查时该要求尚未绑定密钥，运行环境也没有 Token。用户需在环境密钥面板安全填入并发布后生效；本次没有发布环境，没有执行需要认证的真实采集，也没有把公共 Actor 元数据读取算作采集验收。

## 验收仍需分开

真实网站成品必须有实际采集来源、选题的信息价值、编辑过的正文、适合内容的图片与文字编排，以及对最终文件的桌面、手机、交互和全部 PDF 页图审阅。合成执行验证和程序测试不能替代这些要求。

模型仍可能做出弱版式；这需要在实际创作中按技能审阅并修改，不能靠固定模板或成功状态掩盖。FastAI、视频、VIP、线索和发布服务也没有因原始技能包含参考脚本而自动接通。
