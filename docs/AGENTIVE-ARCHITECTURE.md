# Agentive：模块工作区与上下文助理

用户最新方向：不再以完整 ERP 为产品目标；每个业务模块都有可编辑的 Assistant，交互参考 Shopify Sidekick。本文件确定后续开发方向，已有 ERP 界面和测试记录作为复用资产保留。`dsh-mini-erp@0.5.0` 已提供商品、文件、客户、订单四类助理侧栏、职责／工作指令编辑与原生新会话交接。下表中的能力编辑和内嵌执行结果仍为目标，尚未实现。

## 模块如何工作

一个模块包含业务工作区、Assistant 和助理配置。工作区展示真实资料、选中的记录、当前任务与执行结果；助理根据当前上下文接受自然语言请求，按需调用 Skill 和工具。各模块有自己的助理入口及能力配置，底层沿用 DSH。

桌面端目标布局为业务内容旁的助理面板；窄屏使用可切换的助理视图。当前布局已在真实 DSH Web 的 1440／390px 验证。用户在界面修改资料与助理调用工具修改资料，均通过现有同一服务，结果回到业务工作区。

| 部分 | 含义 |
| --- | --- |
| 当前上下文 | 模块、DSH 工作区、选中的记录 ID／修订、明确引用的文件和当前任务 |
| 可编辑职责 | 助理名称、目标、工作指令和输出偏好 |
| 可编辑能力 | 可用 Skill、工具及其说明；继续遵守 DSH 的实际权限与服务边界 |
| 执行结果 | 已生成的文件、实际工具回执、成功修改的记录，或明确的缺失信息和错误 |

数据来源优先使用宿主可访问的工作区文件、原始附件和现有资料库。云端不能自动读取用户电脑。页面切换时需要明确更新上下文，不能继续把上一模块或另一工作区的选中记录当作当前对象。助理修改记录前重新读取所需修订，已有并发校验和重复请求恢复机制继续生效。

助理按用户任务决定步骤；操作授权沿用会话和 DSH 权限机制。查询、分析、起草和修改的界限由真实工具行为体现。页面状态以工具回执与数据读取为准，不能把模型文字当成已经执行的变更。

## 现有能力如何复用

| 模块 | 助理可依托的现有能力 | 当前边界 |
| --- | --- | --- |
| 商品 | 原产品库、SKU、图片、报价、来源资料与修订检查 | 尚无商品系列服务，不继续按旧 ERP 清单自动补齐 |
| 文件 | 原始附件、版本、搜索与确切来源读取 | 不复制附件或自动扩大文件访问范围 |
| 客户 | 工作区客户读取、创建、编辑与关联订单 | 原 ID、联系方式和内部备注保留 |
| 订单 | 现有预留、确认、取消及幂等回执 | 不等于付款或履约；保持账本原有语义 |
| 微刊 | 现有独立微刊 Skill、选配模块与唯一编译器 | 对话发起创建，真实来源与未发布状态保持清楚 |

前四类模块已接通原生会话入口；微刊沿用独立 Skill。工具名称提示帮助选择能力，不是工具权限隔离。未实现服务继续显示真实状态。现有记录保留；此次方向调整不删除数据、不自动迁移数据库，也不把历史订单重新分类。

## 接入方式与首个验收

执行宿主继续使用 DeepSeek Harness。已核对官方 `0.2.1-rc.2` 的 Agent preset、persona、工具作用域与原生会话入口：预设可以组合能力，现有预设界面主要支持选择和查看；业务模块现可直接编辑职责和工作指令，作为新会话的用户任务上下文。运行中的会话与新配置的生效关系必须明确，不静默修改正在执行的任务。

当前路径：打开模块或记录 → 点击「助理」 → 编辑任务 → 「进入助理会话」 → 在原生 DSH 输入框检查并发送。每次创建新的 `standard` 会话，不覆盖已有会话草稿；原生会话保留执行记录。页面有未保存更改时禁止启动，切换模块／工作区／记录时清空旧任务上下文。返回模块重新读取现有业务服务。

配置以 `agentive:assistant:<module>` 保存到当前浏览器 localStorage，按模块区分，不是服务器配置、跨浏览器同步或 Agent preset／persona。修改不会改变已经创建的会话。当前未提供助理名称、Skill 或工具权限编辑器，也未在侧栏内嵌流式对话与工具结果。资料库仍是 profile 级；客户、订单沿用工作区隔离。

验证：配置保存、模块／工作区切换及未保存保护的 DOM 检查通过；真实 DSH 创建新会话、保留 binding、填入模块／工作区／任务草稿并打开会话通过。已尝试发送“只读查询商品数量”，宿主返回 `MISSING_CREDENTIAL`（`deepseek-official` 路由没有 API Key），未发生工具调用，不能声称模型端到端任务验收成功。需在 DSH 模型设置配置凭据后继续验收真实读取／修改与结果回显。
