# Agentive：模块工作区与上下文助理

用户最新方向：不再以完整 ERP 为产品目标；每个业务模块都有可编辑的 Assistant，交互参考 Shopify Sidekick。本文件确定后续开发方向，已有 ERP 界面和测试记录作为复用资产保留。本轮仅记录架构约定，尚未实现模块助理入口或配置编辑器。

## 模块如何工作

一个模块包含业务工作区、Assistant 和助理配置。工作区展示真实资料、选中的记录、当前任务与执行结果；助理根据当前上下文接受自然语言请求，按需调用 Skill 和工具。各模块有自己的助理入口及能力配置，底层沿用 DSH。

桌面端目标布局为业务内容旁的助理面板；窄屏使用可切换的助理视图。具体布局是实现方案，需要通过实际 DSH 接入验证。用户在界面修改资料与助理调用工具修改资料，均通过现有同一服务，结果回到业务工作区。

| 部分 | 含义 |
| --- | --- |
| 当前上下文 | 模块、DSH 工作区、选中的记录 ID／修订、明确引用的文件和当前任务 |
| 可编辑职责 | 助理名称、目标、工作指令和输出偏好 |
| 可编辑能力 | 可用 Skill、工具及其说明；继续遵守 DSH 的实际权限与服务边界 |
| 执行结果 | 已生成的文件、实际工具回执、成功修改的记录，或明确的缺失信息和错误 |

数据来源优先使用宿主可访问的工作区文件、原始附件和现有资料库。云端不能自动读取用户电脑。页面切换时需要明确更新上下文，不能继续把上一模块或另一工作区的选中记录当作当前对象。助理修改记录前重新读取所需修订，已有并发校验和重复请求恢复机制继续生效。

助理按用户任务决定步骤；操作授权沿用会话和 DSH 权限机制。查询、分析、起草和修改的界限由真实工具行为体现。页面状态以工具回执与数据读取为准，不能把模型文字当成已经执行的变更。

## 现有能力如何复用

| 模块 | 助理可依托的现有能力 | 当前边界 |
| --- | --- | --- |
| 商品 | 原产品库、SKU、图片、报价、来源资料与修订检查 | 尚无商品系列服务，不继续按旧 ERP 清单自动补齐 |
| 文件 | 原始附件、版本、搜索与确切来源读取 | 不复制附件或自动扩大文件访问范围 |
| 客户 | 工作区客户读取、创建、编辑与关联订单 | 原 ID、联系方式和内部备注保留 |
| 订单 | 现有预留、确认、取消及幂等回执 | 不等于付款或履约；保持账本原有语义 |
| 微刊 | 现有独立微刊 Skill、选配模块与唯一编译器 | 对话发起创建，真实来源与未发布状态保持清楚 |

这些是已有能力映射，不表示模块助理已经接通。未实现服务继续显示真实状态。现有记录保留；此次方向调整不删除数据、不自动迁移数据库，也不把历史订单重新分类。

## 接入方式与首个验收

执行宿主继续使用 DeepSeek Harness。已核对官方 `0.2.1-rc.2` 的 Agent preset、persona、工具作用域与原生会话入口：预设可以组合能力，现有预设界面主要支持选择和查看；业务模块配置的直接编辑入口仍需接入。运行中的会话与新配置的生效关系必须明确，不静默修改正在执行的任务。

先完成商品模块的一条真实路径：选择已有商品或工作区资料 → 打开带有当前上下文的商品助理 → 按请求读取、整理或修改 → 原产品库与页面显示实际结果。同步验收修改助理配置、新会话使用新配置、工作区切换、错误恢复及原有数据保护。通过后复用同一接入方式到其他模块。

不新增独立 Agent Loop、聊天记录库、阶段引擎或交易状态库。保留现有 DSH 会话和工具作为可检查的执行记录。

参考对象：[Shopify Sidekick](https://www.shopify.com/sidekick)、[官方帮助](https://help.shopify.com/en/manual/shopify-admin/productivity-tools/sidekick)。本次环境网络策略阻止读取这两个页面，因此这里记录的是用户指定的交互方向与本项目设计，不声称核验了 Sidekick 的最新功能全集或可编辑能力。
