## 本次交付边界

本次完成的是插件清单、发布审核和**工具选择管理**的下一轮代码与专属回归，不是完整插件商店上线。保持 Draft；没有合并 main、修改生产配置、访问真实企业数据、调用模型、执行外部业务、拉取镜像或部署。

### 原 Host 接线

插件库由原 `createApp` 独立创建、挂载和关闭；恢复 Medusa 原装配函数的单一职责，不再把管理功能挂在 Medusa service 上。GET 仍经过原身份入口；POST 仍经过原请求体签名与隐私门。关闭与初始化失败分别释放管理模块。

企业模式必须注入原 `access.nativeSessionById`。读取、写入、暂存文件之后/提交之前、最终响应前都复核当前 Session，而不是相信请求开始时保存的 role/到期信息。原响应函数增加仅供受信调用者使用的同步 `beforeWrite` 回调，在原审计 await 后、输出前再检查；现有三个参数的调用保持兼容。

**不宣称跨授权系统与文件 rename 的原子撤权，也不宣称全 Host 签名入口已经实际验收。** 原审计追加与响应输出本来就是不同步骤，本次的最后检查用于拒绝已失效身份继续接收管理结果。

### 精确请求与恢复

- 修复历史回执与可变 intent 共享对象：保存时复制结果，取消或应用不会改写过去的回执。
- 已有精确请求先核对原 fingerprint，再返回原回执；源目录后续变化不造成同一请求重复执行。换内容复用同一 requestId 仍拒绝。
- `GET /api/plugin-library/requests/:requestId` 保留原回执，另外返回 `currentRevision` 和 `currentIntent`；历史事实与当前进度分开。
- 新增 `POST /api/plugin-library/requests/:originalRequestId/cancel`，原签名管理员提交 `{requestId, expectedRevision, intentId}`。只能取消自己的待应用请求；正在应用/已完成的请求不被伪报成取消。
- 新请求固定 24 小时有效期；离线应用在准备与写入前检查。旧记录缺少有效期或已过期时拒绝自动应用，需要新的明确审阅，不迁移旧授权。
- 保留原独占控制记录锁、配置事务标记和人工核对；不自动偷锁、不自动删除中断标记、不触发业务重试。真实子进程异常退出用例证明遗留 writer.lock 会阻止另一个写入者。

### 清单与发布证明

扫描过程中比较 manifest/入口/Skill 的发现身份，对包字节二次核对，并有界读取，拒绝“显示旧版本、指纹却来自新字节”的混合快照。它是有限时点的来源快照，不是恶意同操作系统账号的沙箱。

签名要求规范 Base64 编码；容器可执行路径拒绝点段、重复斜线等非规范表达。发布者失去信任后，既有清单仍可被管理员下架，但不能继续发布或导出为受信制品。没有安装或执行容器。
