# ERP Admin UI/UX 插件包

用户确认：ERP 保留在 DSH 内，一次实现完整后台 UI／UX，接通已有能力；未实现的服务明确显示未接入。此次范围取代此前逐页迭代的限制，不扩大交易后台能力或建立第二套业务库。

## 设计依据

采用 Shopify Admin 的资源导航、页头操作、筛选列表、主辅栏详情和分栏设置结构。参考官方归档 Polaris 文档：[资源列表](https://github.com/Shopify/polaris/blob/3f7954ae42fabf26d63cee68c23ceebfd7ef0972/polaris.shopify.com/content/patterns/resource-index-layout/variants/default.mdx)、[资源详情](https://github.com/Shopify/polaris/blob/3f7954ae42fabf26d63cee68c23ceebfd7ef0972/polaris.shopify.com/content/patterns/resource-details-layout/variants/default.mdx)、[应用设置](https://github.com/Shopify/polaris/blob/3f7954ae42fabf26d63cee68c23ceebfd7ef0972/polaris.shopify.com/content/patterns/app-settings-layout/variants/default.mdx)。

官方 React 仓库已归档，当前环境访问 Shopify 帮助站受限。这里交付既定范围的导航与页面结构，不声称与 2026 年 Shopify 每项功能或像素完全一致。未复制 Polaris 组件源码、商标或示例图片。当前界面使用 Radix Themes 3.3.0 与 Lucide React 1.61.0，应用 CSS 负责布局和少量密度调整；英文与数字内置 Inter 可变字体，中文使用本地系统字体栈。下方 0.3.x 为历史迭代记录，现行视觉以 0.4.0 为准。

## 页面与能力

43 个页面入口共用一套壳层、搜索、导航、状态与响应式布局。

| 范围 | 已完成的页面／交互 | 真实业务能力 |
| --- | --- | --- |
| 首页 | 实际记录数量、资料准备清单、快捷入口 | 原库商品数量、当前工作区客户／订单／有效预留数量；没有模拟销售收入 |
| 商品 | 全库列表、搜索、状态筛选、排序、分页、选择导出；原编辑器内创建／编辑 | 原 Product、SKU、图片、阶梯报价、规格与确切资料版本；未绑定库存的商品同样可见 |
| 客户 | 工作区搜索、创建、编辑、详情、订单历史与订单跳转 | 原 buyer 数据与修订校验；保留旧 ID 和 contact，不猜测拆分邮箱／电话 |
| 订单 | 工作区搜索、状态筛选、创建预留、详情、确认／取消、结果不明时恢复同一请求 | 既有单 SKU 预留／确认；没有付款、履约或真正的草稿订单 |
| 库存 | SKU 关联、当前分配与可供应数量、数量维护 | 既有累计分配账本；不是地点现存量 |
| 内容／文件 | 全库文件搜索／筛选／排序／分页、上传、元信息、版本、预览／下载、归档 | 复用原库文件与宿主附件；ERP 文件页不显示旧自定义审核流程，原库能力保留 |
| 设置 | 二级设置导航；店铺名称／介绍保存；深色／浅色／跟随 DSH、列表密度 | 店铺资料沿用原企业资料；显示偏好只保存在当前浏览器 |
| 其他页面 | 草稿订单、弃单、产品系列、采购订单、转移、礼品卡、客户细分、营销／活动／自动化、折扣、元对象、菜单、博客、市场、分析／报告／实时视图、财务、在线商店／主题／页面／偏好、应用及其他设置 | 页面有对应说明、列表字段或能力分组和明确的未接入状态；没有虚构记录、假连接或假保存 |

订单／客户搜索在数据库分页之前执行；其状态筛选与排序仍作用于当前结果页。库存搜索／筛选仅作用于当前页。商品／文件的搜索、状态和排序均在原库分页之前执行，每页 50 条。导出只包含当前页选中的真实记录，CSV 对公式前缀进行转义。

全局搜索支持 Cmd/Ctrl+K、方向键、Enter、Esc、焦点约束与关闭后返回焦点。每个来源最多 10 条，来源为企业资料库、当前工作区客户、当前工作区订单；部分来源失败会显式提示。商品／文件为 profile 级数据，不应把工作区切换理解为多商家资料隔离。

URL 的 `erp_page` / `erp_workspace` 保留页面与工作区位置，支持浏览器前进／后退；不提供单条记录深链接。未保存表单在切换／关闭页面时受保护；未提交内容不永久保存。已提交但结果不明的客户／订单请求沿用原 requestId 恢复机制。提交中禁止跳转。窄屏侧栏可折叠，设置和表单自动改为单栏，表格可在内部横向滚动。

## 0.3.1 交互与图标打磨

主要导航采用自绘 20px 面型图标，操作图标沿用统一的线框风格；统一按钮、输入框与列表的悬停／按下／键盘焦点样式。当前分组与子页面区分选中层级，展开箭头随状态旋转，图标按钮具有文字提示。窄屏菜单保留图标并增大点击区域。

全局搜索使用 combobox／listbox：方向键切换结果时保留输入焦点，Enter 打开，中文输入法确认不触发跳转；分组展示来源、支持清空与失败重试，输入变化时不显示上一条查询的结果。Esc 返回原触发按钮，打开记录后转移到页面标题。快捷键提示按系统显示 Ctrl K 或 ⌘ K。

列表显示部分选择的半选状态，刷新后清理不存在的选择，支持一键清空搜索并保留输入焦点。修正旧样式导致菜单被遮罩盖住的层级问题，真实指针点击可打开页面；移动菜单打开时背景内容不可聚焦，Esc／关闭按钮返回菜单触发器；宿主布局变宽时自动收起。文件元信息与版本编辑只有存在未保存更改时才确认放弃，保存中禁止取消。

新增交互由临时真实 HTTP DOM 检查覆盖；真实 DSH Chromium 检查搜索连续输入／方向键／Enter／Tab／Esc、移动菜单焦点和宽度切换。没有增加业务模块或改动交易数据模型。

## 0.3.2 紫黑主题

按用户指定，将墨黑背景、紫调卡片、淡紫图标和亮紫主要操作统一为同一套颜色变量。选中态用紫色底与侧边标识，输入框更深一层；首页准备卡片加入低对比度的弧线装饰。商品原编辑器、文件、设置、搜索和手机菜单共用配色，不改动业务数据或流程。成功／警告／错误继续使用独立的语义色。

新浏览器默认选择紫黑；已保存的外观选择继续保留。浅色与跟随 DSH 仍可选择，后者遵循宿主的 color-scheme。当前验收实例通过 DSH 原生设置切为深色，ERP 不通过样式修改宿主导航。

真实 Chromium 检查 43 个页面在 1440／768／390px 下无页面横向溢出或运行异常，键盘搜索与手机指针点击通过。商品／客户／订单／文件表单、原库文件保存等已有 DOM 检查通过；浅色／跟随宿主／紫黑切换及刷新后重新进入的偏好保留通过。主要正文、次要文字、操作按钮和状态文字配色对比度抽查均大于 4.5:1；这不是完整无障碍认证。

## 0.3.3 字体层级

全后台共用字号角色：页面标题 28/36px、首页重点标题 24/34px、卡片标题 16/24px、正文 14/22px、控件 13/20px、辅助说明 12/19px、关键数字 38/44px。标题使用 700 字重，正文与说明使用 400；不再依靠几个难以区分的中间字重表达中文层级。手机页面标题缩至 24px、重点标题 21px、数字 34px，保留层级关系。列表、搜索、设置及复用的商品／文件编辑器均使用同一套角色。

Inter Latin variable 原始 WOFF2 子集来自 `@fontsource-variable/inter@5.3.0`，48,256 字节，内嵌到原生 Client 的 CSS data URL，无外部字体请求或新增服务。字体按 SIL OFL 1.1 分发，插件包含 [完整许可证](../integrations/dsh/dsh-mini-erp/INTER-OFL.txt)。中文沿用 PingFang SC／Microsoft YaHei／Noto Sans CJK SC 等系统字体；不同操作系统的字形仍会略有区别。真实 Chromium 的字体审计确认数字使用内置 Inter，当前云端的中文标题使用 Noto Sans CJK Bold、正文使用 Regular。

字体与留白共同区分页头、指标、重点卡片、字段与说明；数字使用等宽数字和正文亮色，辅助说明降低强调程度。没有新增业务页面、数据或依赖。

本轮验证：`npm run check` 223/223，通过现有 Admin DOM 检查；真实 DSH Web／Chromium 对 43 个页面在 1440／768／390／375px 下检查溢出与运行错误，并复查搜索、移动菜单和四类创建表单。375px 实测页面标题 24px、重点标题 21px、数字 34px。新安装包在干净目录离线安装通过，字体原始字节与 OFL 许可证均随包交付。截图更新为本轮真实空数据 profile；未增加演示记录。

## 0.4.0 Radix Themes 组件库

用户不喜欢此前的自绘风格，本轮实际接入 [Radix Themes](https://www.radix-ui.com/themes/docs/overview/getting-started) 3.3.0 与 [Lucide](https://lucide.dev/) React 1.61.0。按钮、文本输入、文本框、卡片、表格、状态标签、进度条使用库组件；导航与操作图标替换为 Lucide。保留 43 个既有页面及 Shopify Admin 的后台信息结构，没有增加业务模块。

默认深色改为中性黑灰，紫色用于主要操作、品牌与交互重点；删除紫色大面积染色、装饰弧线和自绘图标。首页改为独立概览卡片、设置指南和简洁快捷入口；商品、文件、客户、订单与设置沿用相同控件。原生选择框、复选框和已有搜索／抽屉的焦点逻辑继续保留，不声称所有交互已换成 Radix Primitive。

资料库 1.4.0 的原编辑器接受可选 `ui` 控件适配器，通过 React context 为 ERP 使用 Radix 控件；资料库独立打开时沿用原生样式。没有复制商品／文件／企业的保存逻辑、数据模型或接口。

开发源文件在 `integrations/dsh/dsh-mini-erp/src/`。`npm run build:erp-client` 用锁定的 esbuild 生成同一个原生 `client.js` factory；`npm run build` 和打包脚本也会生成它。React、ReactDOM 与资料库由 DSH 提供，未捆绑第二个 React，也不增加服务进程。Radix 的颜色及组件 CSS 限定在 ERP 根节点，按需保留使用到的组件样式；不向宿主 `:root` 写入变量。字体、图标和组件代码全部随包交付，无 CDN 请求。插件安装与运行不需要前端构建工具；构建依赖仅在仓库开发时安装。

许可见插件内 `THIRD-PARTY-NOTICES.txt` 与 `INTER-OFL.txt`。生成产物保留在仓库，修改应落在 src，避免手改产物后被构建覆盖。

本轮验收：223 项核心检查及六组 Client DOM 检查通过；真实 DSH Web 检查 43 页在 1440／768／390／375px 的布局，随后复查最终首页、商品／客户／订单／文件表单、设置、搜索和手机菜单。未发现页面横向溢出或运行异常。浅色／跟随 DSH 深色／深色及刷新后的偏好保留通过；对宿主的 HTML、body 与六个原生按钮，启用／禁用 ERP 样式前后的颜色、字体、圆角与颜色变量一致。仅代表抽查结果，不是完整无障碍认证。两个新版本原生包在干净临时目录离线安装，通过官方 Cordis／ToolRuntime／附件服务检查，无模型调用。截图来自真实空数据 profile。
