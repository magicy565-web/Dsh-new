# Separately approved missing-step draft repair

This follow-up starts from PR48 `04cbad4ff5f74fa97e46a0845939233ce66cf35f`. The existing draft/publish/status/decision/execution/reconciliation routes and DTO remain compatible. The original fixed PR48 client contract remains valid; `SUPPLIER-DRAFT-REPAIR-CLIENT-CONTRACT.json` is an additive extension.

The new action is `repair_draft`, declared as `supplier.shopify.repair_draft` on the original host adapter. Existing Connectors retain their current capabilities: the service does not silently add/enable this action. A reviewed original Connector must explicitly declare it; the Shopify grant remains the existing `write_products` and no new remote grant or credential is acquired.

A repair starts with read-only reconciliation of the original uncertain draft. Only an original partial receipt with the current exact preview, original intent marker, same shop/currency, existing DRAFT product and single variant can be reviewed. The request names the original draft operation and its reconciled remote content hash. The new scope freezes original product/variant/media identities and full observed media/content basis. It gets its own original capability approval and connectorRun.

This repair deliberately contains no product creation, staging, image upload, activation or channel publish call. It completes the missing retail price/SKU step on the same existing variant. If the approved retail goal is already complete at execution, it reads the result and skips the mutation. A change to other content/media, a new unexpected retail value, a cancelled intake, revoked Connector or session stops subsequent writes. Original Store admission prevents simultaneous/unknown writes on this product from authorizing publication.

After a lost product-create response, the original create intent remains unacknowledged. If the exact product marker and READY media are read back, a new review can explicitly approve those observed media IDs/URLs as its baseline. Private source uploads must already have their original acknowledged SHA receipts. Known media cannot be replaced through this repair. New provenance says `separately_approved_observed_ids_and_shopify_status`, never an invented create receipt or equality proof for transformed CDN bytes. Original create/upload steps and failed original connectorRun remain unchanged; the new repair links through `original.repairedBy`. A verified repair can resolve the original business draft receipt while preserving this attempt history.

Unknown repair outcomes keep the new original operation and consumed approval. Reopen and `shopify-reconcile` perform reads only. Even if the root draft is read-confirmed complete, an unknown repair must be reconciled before publication admission. Actual publication still needs a separate exact-channel approval. Active products, publication-intent markers and any already admitted original publication are not repaired or rolled back as DRAFTs.

Blocked limits are explicit: failed/missing/unready/substituted media need their original source/process reviewed; this action does not transfer replacement files. A remotely edited previously acknowledged variant is a separately scoped update, not a missing-step repair. An absent or unowned product cannot be reconstructed automatically. These limits prevent unconditionally repeating uploads, creating a second product or reissuing channel publication.

At the first checkpoint, focused original-plus-repair tests40/40 and TypeScript/Vite build passed. The cases use an actual local HTTP fixture and original Store/capability service, not an actual shop. A fresh full regression follows. No production, real account, external write, payment, new grant or credential was used. This is ordinary business recovery verification; the blocked independent audit is not repeated or replaced.
