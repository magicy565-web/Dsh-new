# 买手微刊架构边界

用户在 2026-10-26 明确：通过对话创建微刊；资料来自用户电脑工作区或通过工单上传的服务器文件；交易动作搭配 ERP。

## 创建与生成

用户用对话说明读者、本期目的、资料范围和所需模块。Agent 按要求组织本期 blocks，调用必要的资料读取工具，再由渲染器生成微刊。没有独立可视化编辑器或模块选择后台的开发需求。

DSH 负责模型、会话和工具执行；buyer-magazine Skill 负责编辑方法；十个模块定义内容结构；渲染器负责输出 HTML。各期的模块选择及顺序可以不同，同一模块可用于不同产品。

## 两种资料入口

| 入口 | 读取方式 | 来源记录 |
| --- | --- | --- |
| 用户电脑工作区 | 本地运行的 Agent 通过原生文件工具读取用户指定范围；云端执行时需要已经存在的本地接入、同步或上传能力 | 原文件名称、版本或读取时间、页码／表格位置 |
| 工单上传到服务器 | 根据当前用户及工单读取已上传附件，通过实际可用的附件接口交给 Agent | 工单号、附件标识、版本、文件内位置 |

云端工作区不是用户电脑。没有本地接入时，不能把用户电脑路径当成云端可读取路径。服务器附件读取也不能仅凭一个工单号就宣称成功；必须由实际接口返回当前任务可访问的文件。

产品资料、图片、报价、成本和历史销售均可来自这些文件。历史销售即使源于第三方工具的导出表，仍保留原始统计口径、期间、币种和估算标记。读取了文件不等于证明其中所有商业事实正确。

工单用于提交创建要求、关联上传资料和接收生成结果。当前不把工单扩建为客户关系或经营管理系统。

对外微刊只展示适合读者的资料和引用；内部电脑绝对路径、私有附件地址、工单访问凭据不直接写进 HTML。来源追溯信息可保留在任务工作区，公开引用使用可披露的文件名、版本及说明。

## ERP 交易边界

ERP 是报价、样品订单、采购订单、库存、独家供货权益和名额预留等交易状态的权威来源。

- 内容生成阶段可以使用工作区资料或工单附件中的商业条件，但文件中的库存或名额只是有时间的快照。
- 微刊中的交易入口指向已配置的 ERP 页面，或经实际 ERP 适配工具发起已获授权的操作。
- 实际锁定时由 ERP 核对权益、可用量和交易条件；只有 ERP 返回明确成功及对应业务记录，才可表示锁定成功。提交申请、超时或未知结果都不等于成功。
- 工单状态、微刊页面点击和本地 HTML 不承担订单或名额状态；也不维护第二套库存和交易账本。

具体 ERP 尚未指定，不预设为 Medusa 或任何其他产品。连接方式、业务对象和操作接口应以选定 ERP 的实际能力为准。

## 已实现与待接入

已实现：对话使用的 Skill、十个可组合内容模块、JSON 输入、HTML 渲染、计算与来源展示，以及外部操作链接。

已有运行能力：DSH 原生文件／附件能力可读取其实际工作区和可用附件。这里尚未验收用户电脑工作区接入或用户所述工单上传接口。

待接入：实际工单附件来源、部署方式所需的用户电脑文件接入，以及指定 ERP 的查询和交易操作。现有 HTML 链接能力不等于这些集成已经完成。

后续开发围绕这些实际接入点推进。可视化创建后台、独立 ERP、通用资料管理平台均不属于本产品边界。
