# Workspace 插件开发规范入口

这套文档面向后续所有插件开发者与审查者。它规定长期开发方式，配套可重复使用的上手步骤、模板与准入清单；不绑定某次 PR、服务器、分支、SDK 版本或插件数量。

规范版本：**1.0.0**。规范修订与例外规则见 [PLUGIN-STANDARD.md 第 2 节](PLUGIN-STANDARD.md#2-规范治理与责任)。项目维护者负责批准规范修订，具体插件维护人与每次集成／发布责任人由对应 README 和交付记录指定。

## 从哪里开始

| 你要做什么 | 阅读顺序 |
| --- | --- |
| 第一次开发插件 | [长期标准](PLUGIN-STANDARD.md) → [新人指南](DEVELOPER-GUIDE.md) → [模板](PLUGIN-TEMPLATES.md) |
| 修改已有插件 | 该包 README／AGENTS／Skill → 标准相关章节 → 兼容与迁移模板 → [准入清单](ACCEPTANCE-CHECKLIST.md) |
| 审查或集成 | 标准 → 变更契约 → 已填写的准入清单 → 对应版本的证据记录 |
| 判断能否宣称完整业务模块可装卸 | 标准第 3、11、14 节；不能只看 npm 包或工具注册成功 |
| 查某个版本到底实现、测试了什么 | 阅读对应源码和版本验收记录；本入口不替代它们 |

## 文档层级

1. **长期规范**：[PLUGIN-STANDARD.md](PLUGIN-STANDARD.md)。MUST／SHOULD／MAY 是开发要求；不表示旧包已经全部满足。
2. **操作指南**：[DEVELOPER-GUIDE.md](DEVELOPER-GUIDE.md)。给出选边界、读代码、写契约、实现、验证、审查和集成流程。实现映射以当期仓库为准，脚本和接缝变化时同步维护。
3. **复用模板**：[PLUGIN-TEMPLATES.md](PLUGIN-TEMPLATES.md)。README、开发说明、Skill、契约、迁移、证据和 PR 模板。占位内容必须替换；模板不是新的运行时 API。
4. **准入记录模板**：[ACCEPTANCE-CHECKLIST.md](ACCEPTANCE-CHECKLIST.md)。每次变更复制填写；记录版本、证据、未验项、批准与例外。空清单不是验收证明。
5. **版本快照／验收记录**：保存某次源码、环境、实际结果和限制。必须有版本与范围，不能把历史通过直接搬到当前交付。

运行时资料另有明确分工：README 供使用者，AGENTS 供开发维护，Skill 供模型经原生 loader 读取，企业资料与记忆由原业务系统管理。普通资料不能覆盖受信手册或 Host 授权。

## 与既有文档的关系

既有 [插件开发交付手册](../PLUGIN-DEVELOPMENT-HANDBOOK.md)、[实现审计](../PLUGIN-IMPLEMENTATION-AUDIT.md) 和 [交付检查记录模板](../PLUGIN-DELIVERY-CHECKLIST.md) 保留为版本快照与背景证据，不删除、不改写历史结果。后续通用开发要求以本目录的长期标准为入口；历史文件中的临时协作限制、固定版本、未跑项和当时实现数量不自动成为永久规范。

[Factory 插件接口契约](../FACTORY-PLUGIN-INTERFACES.md) 等专题文档仍是对应接口的重要参考。它们可能同时含历史背景、已实现契约和当时的建议；使用前必须对照当前源码，不能仅凭旧文档建立新接口或假定建议已落地。

发现规范、专题文档和代码不一致时：记录冲突，核实当前行为与风险，由相应维护者决定修代码或修文档。不得悄悄忽略规范，也不能因规范写了目标就宣称源码已经支持。

## 核心原则

- 使用原 OMP 工具／Skill／Session；不另造模型循环或插件平台。
- 模型按目标组合能力、追问和调整；后端守住原权限、预算、审批、数据与可靠性。
- 独立插件可以依赖受控 Host；包可加载和完整业务模块可装卸分别证明。
- 原生 JavaScript 是可信执行代码；工具权限不是恶意代码沙箱。
- 默认为无凭据、合成数据的开发验收；真实服务、模型、资料披露和生产发布分别核准。
- 规范文档、PR 合入和测试通过都不授予账号、付费、部署或数据访问权限。

## 维护方法

修改本目录时，提交说明必须写清：规范版本变化、受影响条款、兼容影响、示例／路径校验和是否需要旧插件迁移。长期规则留在标准，易变化的源码映射留在指南，单次测试和版本差异留在独立验收记录。不要把所有信息堆回一份“最新验收快照”。
