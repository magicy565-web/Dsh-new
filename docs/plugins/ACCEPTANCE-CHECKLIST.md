配套规范：**1.0.0** · [标准](PLUGIN-STANDARD.md) · [指南](DEVELOPER-GUIDE.md) · [模板](PLUGIN-TEMPLATES.md)

> 为每次插件变更复制一份并填写。每项填写“通过／失败／未执行／不适用＋理由”；空项不是通过。此表不是运行许可，不授予安装代码、披露资料、付费、凭据操作或生产发布权限。仅文档变更可以缩小验证范围，但必须说明理由，不能由此宣称代码验收通过。

## B. 插件边界与自主性

- [ ] 三层责任、原业务权威和外部依赖清楚，没有把外部服务插件计为 OMP 工具包。
- [ ] 独立打包／原 SDK 加载／Host 可选挂载／完整业务模块分别声明。
- [ ] 无 Host 时明确未配置或只提供已声明的纯能力。
- [ ] 没有另造 Runtime、模型 Loop、业务规则引擎、重复数据库或调度权威。
- [ ] 模型可按目标追问、跳过、调整和停止；未强迫所有任务经过固定业务 DAG。
- [ ] 必需安全／事务状态机、真实前置条件、已批准准入政策、业务建议分开。
- [ ] 没有未经明确批准删除或变更现有准入政策。
- [ ] 若声明完整模块，已列 Host／RPC／任务／界面／服务全部接缝和剩余静态绑定。

## C. 包与供应链

- [ ] 名称、工具名和 Skill 名唯一；改名或删除有兼容计划。
- [ ] manifest 使用真实支持字段；入口、files、extension、Skill 与制品一致。
- [ ] 包内 import／资源不逃出包；外部依赖和 peer 已声明并实际核对解析布局。
- [ ] 锁、SDK、运行时 verifier、完整性记录和目标平台一致。
- [ ] 注册阶段无业务请求、模型请求、凭据扫描或隐式持久化。
- [ ] 无未审查安装／构建 hook、动态下载或隐式账号配置。
- [ ] 第三方代码来源、许可、版本、完整性和文件／网络／进程行为已审查。
- [ ] 明确原生 JS 运行在受信环境；未把 manifest／授权门／静态检查说成恶意代码沙箱。
- [ ] 若需要不可信代码隔离，已有单独批准、实际实现和验证；未假定原 loader 提供。
- [ ] 新可选插件默认不激活，或有批准产品配置；既有默认行为变化有兼容审查。
- [ ] 无秘密、真实运行数据库、原始模型上下文或私有业务资料入包／PR。

## D. 契约、错误、取消与幂等

| 工具／原接口 | 输入限制 | 输出与错误 | 副作用／提交点 | 幂等与未知结果规则 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

- [ ] 工具描述说明用途、费用／外传／写入与未配置状态。
- [ ] schema 与直接 Host 运行时校验一致；非法／额外／过大输入明确处理。
- [ ] 联合选择使用完整元组校验，未意外放大资源、方法、接收方组合。
- [ ] 未用静态 status 冒充真实服务健康或授权有效。
- [ ] 原业务服务、Store／Artifact 仍是权威，未在插件内复制第二份事实库。
- [ ] 成功、失败、部分完成、取消和结果未知按原契约准确区分。
- [ ] 错误内容稳定、可处理且脱敏，无任意 stack／私有响应泄露。
- [ ] 取消信号贯穿适用边界；提交后取消不虚报回滚。
- [ ] request ID 绑定作用域与精确输入，同 ID 改输入不会静默变新操作。
- [ ] 只有原接口明确幂等且当前授权有效时才允许同 ID 精确重试。
- [ ] 未知写入／付费先只读对账或有权人工处置；无自动换 ID 盲重试。
- [ ] 超时、重试、并发、大小及费用有界；不会因示例成功移除限制。

## E. 原授权与最终披露

- [ ] 身份与权限由原可信 Host 绑定；模型参数、Skill 或工具正文不能自授权。
- [ ] 适用的用户／租户／workspace／会话／Run 所有权与有效性已核对。
- [ ] 接收方、用途、选中资源／字段、来源版本／SHA 的约束明确。
- [ ] 原调用前、提交点、恢复／缓存、provider 发送和最终披露检查均保留。
- [ ] 错误／部分结果带私有来源时仍受最终披露门约束。
- [ ] 回执／hash 只作来源证据，不是可重放授权令牌。
- [ ] 撤权、取消、接收方改变、源变化和插件禁用有适用拒绝路径。
- [ ] 旧历史缺必需守卫／版本／授权时 fail closed；未通过改回执或降级权限绕过。
- [ ] 真实历史恢复与迁移仅在其明确授权范围内验证；没有重试仍被拒绝的操作。

## F. 手册、配置、记忆与数据

- [ ] README 有维护者、能力、依赖、配置、权限、副作用、生命周期与证据入口。
- [ ] AGENTS 仅用于开发维护，未被当作自动加载的运行时手册。
- [ ] Skill 的 name／description、目标判断、工具、追问、停止与副作用说明完整。
- [ ] 原 loader／reader 实际可发现并读取 Skill；声明存在不能替代加载证据。
- [ ] Skill 允许模型自主组合，不要求每次都保存、评分、创建决策或调用工具。
- [ ] 普通资料／企业记忆不能覆盖受信策略手册；有相应注入负例。
- [ ] 企业事实使用既有存储与来源规则；不把客户当前业务事实固化进开发说明。
- [ ] 配置、功能选择、用户授权和秘密分离；秘密只由批准来源注入。
- [ ] 数据归属、保留规则、缓存失效、更正／删除责任与对外传输范围明确。
- [ ] 日志和证据脱敏最小化，必要关联 ID 不变成新的敏感数据泄漏。

建议负向用例，按风险勾选并链接实际测试：

- [ ] 无配置、缺 peer、入口缺失、损坏 manifest、同名工具。
- [ ] 错类型、额外字段、过大输入、错误联合选择。
- [ ] 跨用户／租户／会话／Run、错接收方、源版本变化、撤权。
- [ ] before-call／during-call／after-commit／before-delivery 取消。
- [ ] 并发、同 ID 改输入、精确重试、部分提交、未知应答。
- [ ] 错误正文泄露、资料指令注入、伪造回执。
- [ ] 禁用、物理移除、重启、历史拒绝与数据保留。

## I. 例外、审查与发布门

| 例外条款 | 范围／风险 | 补偿控制 | 批准人／负责人 | 到期／复核条件 | 关闭证据 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

- [ ] 例外仅处理获准的工程兼容或流程暂缓，不能代替数据权限、密钥保护、付费或生产授权。
- [ ] 无无限期自动续期；到期未复核时明确阻塞。
- [ ] 独审检查最终文件与被测版本，意见闭环；必要补测已记录。
- [ ] PR 只包含批准的源码、合成测试、契约与脱敏证据。
- [ ] 最终远端提交／制品与整合范围核实；本地和 CI 状态分开。
- [ ] 发布／安装／启用／迁移各有项目批准流程和责任人。
- [ ] 未验关键范围不会以“规范文档已完成”或“PR 已合入”获得生产就绪结论。

## J. 最终结论与签收

```text

有效例外、到期与负责人：
```

签收必须针对明确版本和范围。“代码可合入”“插件可在测试环境启用”“完整模块已验收”“生产获准发布”是不同结论，应分别填写，不使用一个“全部完成”覆盖。
