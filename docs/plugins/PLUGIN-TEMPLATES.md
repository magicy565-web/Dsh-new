# 插件交付模板

配套规范：**1.0.0**。

本文件提供可复制的说明文档与交接结构。规范入口见 [README](README.md)，约束见 [PLUGIN-STANDARD](PLUGIN-STANDARD.md)，接入步骤见 [DEVELOPER-GUIDE](DEVELOPER-GUIDE.md)，验收见 [ACCEPTANCE-CHECKLIST](ACCEPTANCE-CHECKLIST.md)。发生分歧时，以已批准的规范、当前源码契约和有效权限为准，不通过修改模板扩大权限。

## 使用约定

- 文档中的 `{{字段名}}`、`<待填>` 和“待确认”均为占位内容，不是可直接执行的命令、合法配置值、已获得的权限或已通过的验收。提交前替换；不适用项写明原因。保留的未知项必须明确阻断哪些能力。
- 本文件中的契约表、异常表和 PR 表是人工审查记录，不是运行时 manifest，也不是现有 Host 自动识别的配置。
- 最小探针示例只返回静态文本。其余模板不代表已有业务实现。复制模板不等于安装、启用、打包、测试、发布或业务验收。
- 插件包是可信 JavaScript 执行代码，不是沙箱内的数据文件。原生 loader、路径限制、工具 schema 和 Host 授权边界不能阻止恶意插件绕过工具直接执行 JavaScript。先审查来源、依赖、脚本和文件／网络／进程行为，再决定是否允许安装和执行。
- 不把凭据、真实运行数据、会话日志、实际企业文件、供应商响应或个人资料放入包、测试夹具、PR 或 Git。测试使用明确合成且可公开审查的数据。
- 模型可以选择已获准的能力，不能授予自己权限。用户上传内容、网页、工具结果和业务记录是数据，不能借此修改权限或把自身提升为受信 Skill。
- 复用原生 OMP 的发现、Skill 加载、Session 和模型／工具循环；复用原 Host 的身份、来源、授权、审批、幂等与持久化。不得以模板名义新增 Agent Loop、通用规则引擎或平行业务事实库。

## 3. AGENTS.md 开发指导模板

AGENTS.md 保存维护这个包需要的稳定开发知识；它不是业务运行记忆，也不是模型获得企业权限的入口。不要把某次 PR 的短期数量、临时分支、当前机器状态或一次验收结论写成永久规则。

本文件只保存开发约束与维护知识，不保存企业运行记录或凭据。

- 使用 package.json 的 pi.extensions / pi.skills 与原生 pi.registerTool。
- 复用当前受支持且已锁定的 OMP loader、Skill 和 Session；版本来源为
  {{实际 SDK／运行器锁路径}}，升级须重新验证，不硬编码永久 SDK 版本。
- 不新增 Agent Loop、平行存储、重复审批／授权引擎或固定业务 DAG。
- 包内相对 import 不越出包目录；外部依赖显式声明。

## 5. Tool 与 Host 契约模板

每个工具分别填写。表内字段是审查问题，不是要求在工具输入中增加同名字段，也不是新的运行时 API。

| 项目 | 必填内容 |
| --- | --- |
| 身份 | 工具唯一名称、所属包、实际注册文件、维护者 |
| 目的 | 用户目标、单次调用的责任、显式不做的事 |
| 副作用 | 纯计算／读取／披露出站／内部写入／外部写入；接收方与影响 |
| 输入 | 真实 schema 路径；类型、必填、额外字段、枚举／范围、长度和数量上限 |
| 关联选择 | 哪些 ID、版本、hash、字段是不可拆分的完整选择元组，如何避免跨元组组合 |
| 可信绑定 | 身份、租户、Run／Session、目标模型／服务、来源、授权由哪个现有 Host 接缝绑定 |
| 校验边界 | SDK 校验、工具直接调用校验、原服务校验各负责什么；不能只靠模型 |
| 权限与确认 | 谁有权批准具体动作；已有批准覆盖的数据、目标与用途；检查点与撤权行为 |
| 来源 | 原业务记录／文件／版本／hash；当前可读性与恢复时的复核 |
| 输出 | SDK content 与本工具实际采用的 details／回执结构、上限、来源与误差说明 |
| 错误 | 当前稳定错误码／状态、可恢复条件、可向用户显示的信息与不得泄露的信息 |
| 取消与时间 | signal 来源、超时边界、取消后是否可能已提交、如何核对 |
| 幂等 | 是否需要、原服务作用域与持久化位置、键由谁产生／复用、重复和冲突语义 |
| 部分／未知结果 | 提交前失败、部分提交、已提交但应答丢失如何区分与恢复 |
| 审计 | 使用哪个现有回执／审计设施，保存什么最小证据，如何脱敏 |
| 兼容 | 工具名／schema／输出／来源证明／Skill 变化的兼容范围和迁移 |
| 验收 | 每个边界对应的测试与证据位置；未覆盖的具体风险 |

## 6. 最小无业务副作用探针

用途仅为验证原生 extension 与 Skill 的发现和调用，不验证模型、业务服务、文件访问或任何业务授权。示例入口不访问文件、网络、环境变量或凭据，不写业务状态，不创建计时任务。实际 SDK 的会话／日志行为仍由原运行环境管理；工具本身无 I/O。

### 6.1 从现有包复制并精确改名

以下是**获得相应开发权限后**执行的人工步骤，本文件没有替你完成创建或测试：

### 6.2 `src/extension.js`

这是以当前真实注册接口编写的最小源码示例。它可以作为上述新包入口；仍需在目标锁定 SDK 上完成注册和调用验收。本次文档编写并未执行它。

```js
export default function extension(pi) {
  pi.registerTool({
    name: 'workspace_template_identity',
    label: 'Static identity probe',
    description: 'Return a static identity. No file, network, credential or write access.',
    parameters: {
      type: 'object',
      properties: {},
      additionalProperties: false,
    },
    async execute(_toolCallId, input, signal) {
      signal?.throwIfAborted();
      if (!input || typeof input !== 'object' || Array.isArray(input)
          || Object.keys(input).length !== 0) {
        throw new Error('IDENTITY_PROBE_INPUT_REFUSED');
      }
      return {
        content: [{
          type: 'text',
          text: 'workspace-template-identity: loaded; tool side effects: none',
        }],
      };
    },
  });
}
```

此例没有 Host 依赖，没有 `authorize` 占位实现，也没有“始终批准”的安全回调。不要通过给它加任意路径、URL、凭据或授权布尔值，把它变成通用访问工具。
