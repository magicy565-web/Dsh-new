## Implemented closed loop

The machine-readable contract is `contracts/workspace-medusa-business.v1.json`; implementation is in the existing native plugin, not a new service. No schema migration/model was added.

1. Trusted backend authenticates as an existing Medusa user, and receives an explicit product-scoped grant through deployment configuration. Default and malformed configuration deny all. Existing Agent context token, API keys and model-provided actor IDs cannot authorize these routes.
2. `GET /admin/workspace-business/v1/products/:id?include=prices,inventory` returns only projected native fields plus internal summary status/version/source hash. Price and inventory reads each require their own grant; omitting them does not fetch those relationships. Arbitrary `fields`, filters and other query keys are rejected.
3. Task 2 shows the exact proposed summary and the fact that editing withdraws approval; it retains operation UUID, actor, product, old version/hash and proposed value in its existing durable task mechanism. Only after real user confirmation may its trusted host compute the intent digest and send the request. Digest verification binds values; it is **not proof of a human interaction** and must never be treated as one.
4. `POST /admin/workspace-business/v1/products/:id/summary` updates only `agent_summary`, increments the version, sets `ready_for_review`, clears reviewer fields and stores a receipt atomically through the existing conditional DB update. Existing context must already exist. Stale context/product-source observation returns 409. Native product data can still change after observation; this does not approve or publish claims.
5. A lost-response retry with the identical retained intent sees the durable receipt and returns `applied, replayed:true` without another write. Concurrent identical requests share one update. A later different edit returns 409 for old retries; there is no permanent receipt history, so the host must retain an uncertain/conflict state and obtain fresh review rather than manufacture success or silently resubmit.
6. Existing reviewed Agent context remains unavailable until a separate authorized human review. New internal read authorization does not expand the old `title/description/agent_summary` production model allowlist.

Receipt format reuses the already understood `rev:<32hex>:unreviewed` stamp. Existing reapproval hashes include its stamp, and ordinary later edits replace it. Numeric ceiling is explicitly excluded from this write surface. There is no new background queue, generic Admin proxy, token, credential creation or automatic production grant.
