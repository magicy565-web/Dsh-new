## Wake remains a separately verified capability

Official [MCP Events documentation](https://developers.openai.com/plugins/build/mcp-events), checked during this task, describes MCP protocol `2026-07-28`, discovery with an events capability and `events/list`, `events/subscribe`, `events/unsubscribe`. ChatGPT supplies the callback URL and signing secret. A server must validate the signed challenge, persist exact principal/filter/expiry, keep subscription IDs deterministic, and sign subsequent delivery using Standard Webhooks. HTTPS delivery must satisfy DNS/public-address and redirect requirements. HTTP 2xx confirms notification receipt for asynchronous processing; it does not prove an original Muse model turn started.

This task has no account evidence that the original Muse supports that contract or has a valid subscription. The current eleven-operation Connector does not advertise these operations. No new event transport or auth state has been added. Official [scheduled-task documentation](https://learn.chatgpt.com/docs/automations) likewise requires supported account/app authorization; there is no verified original Muse schedule in this task. Existing product Store, receipt/outbox and Host reconciliation remain the monitoring mechanism. No chat automation was created.

`wake.supported:false`, `wake.observed:false`, `executionStartedAt:null` therefore remain truthful. Queue, wake notification receipt, claim, model execution, result bytes, Session return and enterprise acceptance must be displayed separately. A login or reconnect reads and reconciles existing IDs; it never creates another order or sends another model turn.
