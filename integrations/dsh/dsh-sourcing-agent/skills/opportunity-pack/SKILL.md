# 交付物规范

## 渲染契约

产出物由 `sourcing_render` 从项目记录生成，不要手写整份报告：

- `kinds` 选择要生成的文件；不传则生成全部。
- `markdown` 传每个 kind 的叙事正文（结论、推理、建议），会被追加在自动生成的表格之后。表格、金额、名单、闸门状态永远来自记录。
- 重复渲染会覆盖并更新 SHA-256；`dashboard.html` 是阶段、闸门、漏斗与单位经济的一页视图，可直接在侧栏预览。
- 渲染后读返回的 `dir` 与 `written`，确认文件落盘；资产闸门会检查这些文件是否真实存在。

## 文件与命名

- 目录：`<workspaceDir>/sourcing/<slug>/`；固定文件名由渲染器决定（`00-brief.md`、`01-market.md`、`02-buyers.csv`、`03-economics.md`、`04-outreach.md`、`05-launch.md`、`handoff.md`、`dashboard.html`、`data.json`）。
- 另有对外发送的成品（报价单 PDF、品牌手册）放 `assets/`，用日期后缀，不要用 `final-final`。

## 机会报告（`01-market.md` / 客户版 PDF）

结构固定，结论先行：

1. 一句话结论：做 / 不做 / 有条件做，条件是什么。
2. 三个关键判断，每个一句话 + 证据编号。
3. 机会评分表（市场、需求、竞争、合规、物流、毛利）。
4. 目标客户与渠道画像。
5. 90 天行动计划（谁、做什么、何时、花多少）。
6. 风险与待确认项（列明缺什么、怎么补、谁负责）。

正文引用来源编号 `[S1]`，文末列 `sources.csv` 中的链接与访问日期。没有来源的判断标「假设」。

## 表格

- CSV 用 UTF-8 with BOM，保证 Excel 打开中文不乱码；第一行列名用中文，括号内可带英文。
- xlsx 用 openpyxl：冻结首行、列宽自适应、金额列右对齐并带币种、日期列统一 `YYYY-MM-DD`、不使用合并单元格。
- 金额与比率分开列；不要在同一列混放「$12」和「12」。
- 超过 500 行的明细另存一个 sheet，汇总放第一页。

## 文档

- docx：封面（标题、客户、日期、版本）→ 结论 → 正文 → 附录。标题层级只用 Heading 1-3，表格用内置样式。
- 对外发送前转 PDF；文件名带客户名与日期。
- 中文正文用中文标点；英文文案用英文标点，不混排。

## 对外文案

- 英文为主，短句，主动语态，不用 `world-class`、`best quality` 这类无法证明的词。
- 一句一个意思；不堆形容词；不用感叹号。
- 所有性能与合规表述都要有依据，否则删掉。
- 保留中文对照版本供用户审阅。

## handoff.md

必须由用户完成的动作，按五类分组，每条写清「在哪做、填什么、要准备什么材料、预计多久」：

```markdown
## 1. 主体与账户
- [ ] 注册公司主体：…（需要：…；预计：…）
## 2. 店铺与域名
## 3. 支付与收款
## 4. 广告与流量账户
## 5. 认证、物流与售后
```

每条前面用 `- [ ]` 方便勾选；无法确定的地方写「需确认」，不要编造流程。

## 最终回复

- 3 行摘要：做了什么、关键结论、下一步。
- 列出本次新增或更新的文件（相对路径）。
- 用 `present` 交付最重要的 1-2 个文件。
- 不要粘贴整份报告；把细节留在文件里。
