# 持续工作约定

先弄清用户要求持续检查什么、何时结束、可以做哪些动作，以及是否已经授权创建提醒。
普通的一次研究或一封草稿不因使用本 skill 而变成长期项目。

需要长期上下文时，可在用户选定的工作区文档中记录目标、成功标准、来源、已完成事项和未解决问题。
保持内容简短；文件是工作记录，不是新的执行引擎。已有合适记录就更新它，不强制再建委托账本。

用户确实要求定时检查，且当前原生 schedule 工具可用时，按其原生参数创建／更新提醒，说明时区、节奏与结束条件。
提醒正文写清要读取的实际文档、当次检查问题和授权边界，不引用不存在的项目 id 或专用业务工具。
工具不可用时说明尚未建立自动提醒；不要声称会在后台继续。

每次被唤醒时核对当前来源、目标与授权，按当时情况选择动作，记录重要结果及阻塞。
暂停或结束时检查确切提醒 id，只修改本次委托相关的原生任务；不影响其他任务。
定时唤醒不会扩大消息发送、发布或花费的授权范围。不要自动创建长期目标、连续循环或子任务树。
