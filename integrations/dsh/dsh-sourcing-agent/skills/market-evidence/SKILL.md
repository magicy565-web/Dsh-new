# 取证规范

## 写入方式

每条证据用 `sourcing_evidence` 录入：`url`、`title`、`claim`（一句话主张）、`grade`、`publisher`（A 级必填）、`accessedAt`。同一 URL + 主张只记一次，返回的证据 id 供 `sourcing_markets` 的 `evidenceIds` 使用。

闸门要求：每个候选市场至少关联 1 条 A/B 级证据，项目整体 ≥3 条 A/B 级证据。没有证据的市场不会被市场闸门接受。

## 来源分级

| 级 | 来源 | 用法 |
|---|---|---|
| A | 官方统计、海关、法规原文、上市公司年报、平台后台数据（用户提供） | 可作为结论依据 |
| B | 行业协会、展会官网、主流商业媒体、头部咨询报告 | 可作为佐证，需注明口径 |
| C | 平台商品页、卖家自述、B2B 目录条目 | 只能作为线索，写「据平台展示」 |
| D | 论坛、社媒、AI 摘要、二手转述 | 不作为依据，只用于找线索 |

同一个关键数字（市场规模、单价、关税、认证要求）至少要有两个独立来源；只有一个就写「单来源，待交叉核验」。互相冲突时并列两个数字与口径，不要取平均。

## 检索式

- 买家：`"<品类>" importer <国家>`、`"<品类>" distributor <国家>`、`site:kompass.com <品类> <国家>`、`site:thomasnet.com <品类>`、`"<HS 编码>" importer`。
- 竞品：`best <品类> <国家> 2025`、`<品牌名> revenue`、`<品类> reviews complaints`、`site:amazon.<域名> <品类>`。
- 价格：`<品类> wholesale price per unit`、`<品类> FOB price`、`<品类> retail price <国家>`；记录币种、单位、含税与否、日期。
- 法规：`site:eur-lex.europa.eu <品类>`、`site:access2markets.eu <品类>`、`site:fda.gov <品类>`、`site:ftc.gov <品类>`、`site:gov.uk <品类> regulation`。
- 趋势：Google Trends（按国家、近 5 年）、平台 Best Sellers 榜单、展会历年展商数量。

优先用目标市场本地语言再搜一遍（德语、法语、西语、日语），英文结果往往漏掉本地分销商。

## 摘录与登记

每个来源写入 `sources.csv`：`id, url, title, publisher, published_at, accessed_at, grade, claim, quote, currency, unit`。

- `quote` 只放原文短句（≤25 词），不要改写后再当引用。
- 访问日期用当天日期；没有日期的数据标「日期不明」。
- 报告正文引用写 `[S3]` 这类编号，文末列出对应链接。

## 估算与建模

优先自下而上：目标用户数 × 渗透率 × 年均购买次数 × 客单价。参数逐条给来源或标「假设」，并做悲观 / 基准 / 乐观三档。

市场规模（TAM/SAM/SOM）只作为背景，不作为「能赚多少」的证据；能赚多少由单位经济决定。

## 竞品拆解

对每个主要竞品记录：定位一句话、价格带、核心卖点、差评前三类、流量来源（广告 / 自然 / 达人）、履约方式（FBA / 海外仓 / 国内直发）、订阅或复购机制。差评要抄原文并给链接，用于找产品改进点。

## 法规检索

只从官方站点取结论：欧盟 EUR-Lex 与 Access2Markets、英国 GOV.UK、美国 FDA / FTC / CPSC / CBP、日本厚生劳动省与 METI、中国海关总署。写清适用主体（制造商 / 进口商 / 分销商）、产品范围与生效日期。

无法从官方确认的，写「需由检测机构或当地律师确认」，并列出要问的具体问题。

## 禁止

- 编造或猜测 URL、公司名、联系人、认证编号。
- 没打开页面就引用标题或摘要。
- 用三年前的价格当现价而不标日期。
- 把平台展示价、促销价、批发价混为一谈。
- 把「行业平均」当成用户自己的成本或产能。
