# 07 · Magazine storyboard

## Contract

**Input:** editorial plan, product records, available images and target surfaces. **Output:** a section-by-section reading sequence, image plan, and format adaptations. **Consumer:** art direction, layout, and publishing. A responsive magazine is not a fixed slide deck stretched into a browser.

## Build a five-part reading sequence

| Beat | Reader question | Layout and content | Intended reading effort |
| --- | --- | --- | --- |
| Orientation | What is this morning's useful angle? | Masthead, date, lead headline, brief deck, lead visual | 15–25 seconds |
| Signal | Why should I spend attention here? | Short editor note and three concrete signals | 25–40 seconds |
| Opportunities | Which products are relevant? | Usually three product features with evidence and unknowns | 2–3 minutes |
| Decision | How do these options differ? | Comparable procurement rows and a short risk note | 40–60 seconds |
| Next step | What should I ask or save? | Shortlist/inquiry preparation plus source access | 20–40 seconds |

These are planning allocations, not measured interaction analytics. Avoid “5 min read” if actual content greatly exceeds the intended budget.

## Assign one dominant visual per beat

Give the lead the largest visual area. Keep product features visually consistent so differences in the products remain legible. Use detail crops only to explain a useful property. A decorative image between every paragraph destroys comparison and increases download/scroll cost.

Record each intended image with product ID, role, source/permission, crop, focal point, caption requirement, and mobile behavior. If no documentary product image is available, keep a clean text-led feature or an explicitly labelled illustration. Do not invent an image to make the page seem complete.

## Adapt the same content to three surfaces

| Surface | Preserve | Change |
| --- | --- | --- |
| Web magazine | Full core story, evidence, comparisons, sourcing actions | Add shortlist, source drawer, category selection, request download |
| HTML email | Issue angle, short product highlights, key uncertainty, valid links | Remove scripts, drawers, forms and sticky controls; inline layout/styles |
| PDF/print | Full static facts, disclosures, links/source references | Show essential hidden content, remove interactive chrome, control page breaks |

Do not screenshot the whole website into a PDF: text, links and tables need to remain readable. Inspect the browser print result. A long product feature may require a controlled page break; keeping an oversized section unbreakable can produce blank space or clipping.

## Plan mobile first

At 375 px, place category, product title, price basis, MOQ and lead-time status in a coherent vertical flow. Do not make an image taller than necessary to identify the product. Keep procurement labels next to values. Comparison may scroll within a labelled region, but the whole page must not require horizontal panning.

Set a useful natural reading order in the DOM. Desktop columns should enhance this order, not create a different story that screen readers or mobile users cannot follow.

## Define the stopping rule

Stop adding sections when each product's decision can be made and the next step is clear. Do not add a founder story, market essay, factory process, or testimonial unless evidence and audience need justify it. A shorter, well-edited issue is a valid output.

## Gate

Walk the storyboard using only section titles and one sentence per section. Every beat must answer a different buyer question. Reject repeated “why this matters” blocks and layouts that postpone procurement facts until the end. Verify that every interaction has an equally useful static fallback.

**Example failure:** a twelve-screen animated introduction followed by a dense twenty-row table. Repair by placing the decision and key facts in the opening product story, then offering deeper evidence on demand.
